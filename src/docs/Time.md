# Time

The time feature separates current instants, process-local elapsed measurements,
and human-readable presentation. It adds no remote endpoint or dependency.

## Configuration

Set `TIME_CONFIG.DEFAULT_TIME_ZONE` in `src/shared/features/time/config.ts`.
The default is `UTC`; use a timezone supported by Intl, such as `Europe/Paris`.
Set `TIME_CONFIG.LOCALE` in the same config; its default is `en-GB`. It selects
Intl's formatting language, including offset labels. The shared schema rejects
invalid timezones and invalid or unsupported locales. Treat these as project
configuration applied consistently to server and browser builds.

This setting controls timestamp display. It never shifts an instant: Unix
timestamps remain absolute and machine-readable ISO timestamps stay in UTC.
Changing the display setting does not change server operating-system settings.

## Exports and clock choice

Import browser-safe functions directly from their files under
`@/shared/features/time/utils/`, for example:

```ts
import { readCurrentTimestampSeconds } from '@/shared/features/time/utils/readCurrentTimestampSeconds';
import { readStopwatchMilliseconds } from '@/shared/features/time/utils/readStopwatchMilliseconds';
import { formatDateTime } from '@/shared/features/time/utils/formatDateTime';
import { timestampSecondsToDate } from '@/shared/features/time/utils/timestampSecondsToDate';
import { TIME_CONFIG } from '@/shared/features/time/config';
```

There is no time barrel or `src/features/time` folder. The two clock readers are
an explicit exception to the usual pure-utility convention: they read a clock,
but have no network or server-only dependency.

| Export                            | Units/result                         | Use                                                               | Cost                           |
| --------------------------------- | ------------------------------------ | ----------------------------------------------------------------- | ------------------------------ |
| `readCurrentTimestampSeconds()`   | Unix seconds, including fractions    | Application receipt times, token expiry, countdowns               | Synchronous local wall clock   |
| `readStopwatchMilliseconds()`     | Process/page-local milliseconds      | Differences between readings to measure elapsed time              | Synchronous local stopwatch    |
| `timestampSecondsToDate(seconds)` | `Date`, millisecond precision        | Adapt seconds-based timestamps for display or APIs expecting Date | Pure conversion                |
| `formatDateTime(date, timeZone?)` | `YYYY-MM-DD HH:mm:ss.SSS <timezone>` | Human-readable timestamps; defaults to project timezone           | Pure formatting, no clock read |
| `TIME_CONFIG`                     | Validated project settings           | Read the configured display timezone                              | Configuration only             |

`Date.now()` backs application time, so different machines can disagree and
wall-clock adjustments can change it. `performance.now()` backs elapsed time;
its readings cannot be compared between processes/pages, stored as calendar
timestamps, or replayed on another runtime. Neither clock synchronizes machines.

## Conversions and formatting

Keep units explicit in variable names: `operationStartedAtMs` is a stopwatch
reading; stored `operationAt` is Unix seconds. Whole-second protocols
explicitly floor the application-clock result.

`formatDateTime` uses a fixed numeric layout and explicit timezone, including
daylight-saving rules. Offsets outside `UTC` are included so repeated wall times
during the autumn clock change remain distinguishable. Table timestamps expose
the complete value in their title. It reuses the default formatter for repeated table rows.
An explicit timezone overrides the project default for that call. It does not
modify the Date, and invalid dates/timezones throw RangeError. This is a shared
timestamp presentation format with Gregorian dates and Latin digits across locales,
not a localized prose/date-input system. Locale controls Intl's offset label, not
the fixed YYYY-MM-DD ordering; the format remains safe for existing table cells.

Use `date.toISOString()` for machine-readable values and `<time datetime>`;
format the visible text separately. Native timestamp hooks generated by
libraries retain their exact native representations. Do not round-trip millisecond values
through seconds merely to route them through a helper.

## Tests

Feature tests cover timezone/locale validation, fractional/pre-epoch conversion,
configured display, date/year boundaries, daylight-saving transitions, UTC
midnight and invalid inputs.
